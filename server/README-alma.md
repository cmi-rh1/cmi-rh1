# ตั้งซิงค์อัตโนมัติบนเซิร์ฟเวอร์ AlmaLinux

เซิร์ฟเวอร์ `hosoffice` (192.168.6.110) ผ่านเงื่อนไขครบแล้ว เข้า cmi.moph.go.th ได้ เข้า GitHub ได้ มี Python 3.9 และตั้งเวลาเป็น Asia/Bangkok อยู่แล้ว จึงเขียนเวลาใน cron เป็นเวลาไทยได้ตรง ๆ

ระบบจะทำงานแบบนี้ เซิร์ฟเวอร์ดึงข้อมูลจากเว็บ CMI ทุกวันที่ 1 และ 16 เวลา 08:00 น. ตรวจความครบถ้วนก่อน แล้วส่งเฉพาะ `data.json` ขึ้น GitHub หน้าเว็บ GitHub Pages จะอัปเดตตามเองภายในหนึ่งถึงสองนาที ไม่ต้องเปิดคอมพิวเตอร์ ไม่ต้องพึ่ง Task Scheduler

---

## ขั้นที่ 1 อัปโหลดโฟลเดอร์ server ขึ้น GitHub

เข้า https://github.com/treerat1989-beep/cmi-rh1 กด **Add file › Upload files** แล้วลากโฟลเดอร์ `server` ทั้งโฟลเดอร์เข้าไป (ในนั้นมี `sync_cmi.sh` กับ `install_server.sh`) จากนั้นกด **Commit changes**

ถ้าลากทั้งโฟลเดอร์ไม่ได้ ให้กด **Add file › Create new file** แล้วพิมพ์ชื่อไฟล์เป็น `server/sync_cmi.sh` วางเนื้อหาลงไป แล้วทำแบบเดียวกันกับ `server/install_server.sh`

## ขั้นที่ 2 สร้าง token ของ GitHub

เข้า https://github.com/settings/personal-access-tokens/new แล้วตั้งค่า

| ช่อง | ใส่ว่า |
|---|---|
| Token name | cmi-server |
| Expiration | No expiration หรือ 1 ปี |
| Repository access | Only select repositories → เลือก `cmi-rh1` |
| Permissions › Repository permissions › Contents | **Read and write** |

กด **Generate token** แล้ว**คัดลอกเก็บไว้** GitHub จะแสดงให้เห็นครั้งเดียวเท่านั้น

## ขั้นที่ 3 ติดตั้งบนเซิร์ฟเวอร์

ssh เข้าเครื่องแล้ววางคำสั่งนี้

```bash
curl -fsSL https://raw.githubusercontent.com/treerat1989-beep/cmi-rh1/main/server/install_server.sh -o /tmp/install_server.sh
sudo bash /tmp/install_server.sh
```

ระหว่างติดตั้งจะถามหา token ให้วางที่คัดลอกมาจากขั้นที่ 2 (พิมพ์แล้วจะไม่ขึ้นบนจอ เป็นเรื่องปกติ) แล้วกด Enter

สคริปต์จะลงโปรแกรมที่ต้องใช้ โคลนโค้ดไปไว้ที่ `/opt/cmi-rh1` ตั้ง cron ให้ แล้วทดลองดึงข้อมูลจริงหนึ่งรอบให้ดูเลย ใช้เวลาประมาณ 5 ถึง 10 นาที

## ขั้นที่ 4 เปิด GitHub Pages (ถ้ายังไม่ได้เปิด)

ที่ repository กด **Settings › Pages** เลือก Source เป็น **Deploy from a branch** แล้วเลือก branch `main` กับ `/ (root)` กด **Save** รอสักครู่จะได้ลิงก์

```
https://treerat1989-beep.github.io/cmi-rh1/
```

## ขั้นที่ 5 ปิด workflow เดิมของ GitHub

workflow เดิมเข้าเว็บกระทรวงไม่ได้ ถ้าปล่อยไว้จะรันล้มเหลวทุกรอบแล้วส่งอีเมลแจ้งเตือน ให้เข้า repository เปิดไฟล์ `.github/workflows/sync.yml` กดรูปถังขยะเพื่อลบ แล้วกด Commit changes

## คำสั่งที่ใช้บ่อย

| ต้องการ | คำสั่ง |
|---|---|
| สั่งซิงค์เองทันที | `/opt/cmi-rh1/server/sync_cmi.sh` |
| ดูล็อกล่าสุด | `tail -n 40 /var/log/cmi-sync.log` |
| ดูล็อกแบบเรียลไทม์ | `tail -f /var/log/cmi-sync.log` |
| ดูตารางเวลาที่ตั้งไว้ | `crontab -l` |
| เปลี่ยนรอบเวลา | `crontab -e` แล้วแก้บรรทัด `0 8 1,16 * *` |
| เปลี่ยน token | `rm /root/.cmi-git-credentials` แล้วรัน install_server.sh ใหม่ |

รูปแบบเวลาใน cron คือ `นาที ชั่วโมง วันที่ เดือน วันในสัปดาห์` ดังนั้น `0 8 1,16 * *` แปลว่า 08:00 น. ของวันที่ 1 และ 16 ทุกเดือน ถ้าอยากได้ทุกวันให้ใช้ `0 8 * * *` ถ้าอยากได้ทุกวันจันทร์ใช้ `0 8 * * 1`

## ระบบกันข้อมูลเสีย

สคริปต์จะไม่เขียนทับ `data.json` เดิมเลย จนกว่าจะผ่านด่านทั้งหมดนี้

เริ่มจากเช็คก่อนว่าเว็บ cmi.moph.go.th ตอบ HTTP 200 ถ้าเว็บล่มจะหยุดทันที จากนั้นดึงข้อมูลลงไฟล์ชั่วคราว ถ้าได้ข้อมูลไม่ถึง 80% ของจำนวน รพ. สคริปต์จะหยุดและทิ้งไฟล์ชั่วคราว ต่อด้วยตรวจว่าไฟล์ใหม่ใหญ่พอ อ่านเป็น JSON ได้ มี รพ. เกิน 50 แห่ง และมีแถว DRG เกิน 1,000 แถว ผ่านครบแล้วจึงย้ายทับของเดิม สุดท้ายถ้าข้อมูลไม่ต่างจากรอบก่อนก็จะไม่ commit ให้เปลืองประวัติ

ถ้ารอบไหนล้มเหลว ข้อมูลเดิมบนเว็บยังอยู่ครบ แล้วรอบถัดไปจะลองใหม่เอง ถ้า push ไม่สำเร็จเพราะเน็ตหลุด commit จะค้างไว้ในเครื่องและถูกส่งขึ้นในรอบถัดไปโดยอัตโนมัติ

## ข้อมูลที่ต้องดูแลเอง

`hosname.csv` เก็บระดับบริการ จำนวนเตียง และ ปชก.UC ของแต่ละ รพ. มาจากไฟล์ M and E เขตสุขภาพที่ 1 ข้อมูลนี้ไม่ได้อยู่บนเว็บ CMI จึงไม่อัปเดตอัตโนมัติ ถ้าปีหน้ามีตัวเลข ปชก.UC ใหม่ ให้แก้ไฟล์นี้ใน GitHub ได้เลย กดที่ไฟล์แล้วกดรูปดินสอ รอบซิงค์ถัดไปเซิร์ฟเวอร์จะ pull มาใช้เอง

ปีงบประมาณสคริปต์คิดให้เอง เดือนตุลาคมขึ้นปีงบใหม่อัตโนมัติ ไม่ต้องแก้อะไร
